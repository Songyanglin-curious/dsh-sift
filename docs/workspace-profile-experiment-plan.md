# Workspace 类型最小实验计划

日期：2026-09-14。执行：Luna；审查：主代理。

## 目标与范围

在 DSH `0.1.5-rc.2` 上验证工作区可通过 Sift 私有元信息拥有 default/sift 类型，并在原生工作区、会话切换时正确显示。只显示“当前工作区 + 类型”，不实现素材、笔记、三栏布局或类型管理界面，不修改 DSH 安装文件或原生 Workspace schema。

保留当前工作区中的既有改动。本次不自动提交或推送 Git。

## 执行步骤

1. 准备两个测试目录并登记为隔离开发 Home 中的原生 Workspace。default 不含配置；sift 保存 `.sift/config.json`，内容为 `{"schemaVersion":1,"profile":"sift"}`。使用可重复执行的准备方式，避免重复登记和覆盖未知配置。
2. 实现最小 Host 类型读取接口：以 Workspace ID 查原生注册路径，再读固定位置配置；缺失返回 default；格式损坏或版本不支持明确报告，不重写文件。
3. Client 订阅原生会话与工作区状态，推导当前所属工作区并读取类型；在现有适合的插槽显示名称和类型。加载中、无当前工作区、读取失败各有明确状态；过期异步响应不能污染新选择。
4. 执行静态检查、必要单元测试和真实 DSH 集成验证。记录复现命令、测试目录和实机结果；自动化通过与浏览器实测分开报告。

## 验收标准

| 场景 | 预期 |
| --- | --- |
| 打开 default 工作区的会话 | 显示其名称和 default |
| 打开 sift 工作区的会话 | 显示其名称和 sift |
| 两个工作区往返切换 | 名称与类型始终对应，原生会话可正常使用 |
| 快速切换、请求乱序返回 | 旧请求不能覆盖当前工作区结果 |
| 重启开发 DSH 并重新打开工作区 | 类型根据持久化配置恢复，不依赖内存初始化 |
| 移走 sift 配置并重新加载/进入 | 显示 default；恢复文件后可再次读到 sift |
| 损坏配置、未知 schemaVersion | 显示可理解错误与默认处理，不改写配置 |
| 尚无当前会话或无工作区归属 | 显示未选择，不沿用旧名称与类型 |

本阶段不要求文件监视器实时响应外部编辑；必须明确重新读取的触发方式，确保相同工作区重新进入或刷新时不会被永久缓存遮蔽。
