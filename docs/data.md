# 数据模型与迁移

Sift 将关系数据放在 `DSH_HOME/sift/catalog.json`，粘贴文本放在 `DSH_HOME/sift/sources/`。项目成果笔记始终位于所选 DSH 工作区内，不复制进 Sift 数据目录。

## 主要关系

- 解决方案保存 DSH `workspaceId` 和规范化后的 `workspacePath`；多个解决方案可以指向同一工作区。
- 项目只属于一个解决方案，保存一篇 Markdown 路径、素材引用和多个历史 DSH 会话，其中一个为当前会话。
- 素材归一个解决方案所有，项目只保存引用。项目移除引用或解决方案移除素材均不删除原文件。
- 批注保存不可变的引文、来源身份、文档版本和文本/PDF/消息锚点；人的评论通过追加版本修改。
- 发送记录保存会话、排队/转向模式、实际消息文本版本以及发送开始时冻结的批注评论版本。
- 工作现场保存标签、当前阅读位置、未保存草稿及其基准版本、批注勾选、布局宽度和待消费的来源回跳。现场字段以原子补丁写入，避免滚动保存、草稿保存和批注操作并发时用旧对象覆盖其他字段。
- 每次笔记写入保存前后内容和版本；回退本身也形成新修订。

## 一致性规则

笔记路径必须位于解决方案工作区内，且不能同时作为只读素材引用。AI 笔记工具不接受路径或项目标识，而是每次从调用会话反查项目。所有写入和回退都比较当前文件版本，避免覆盖并发或外部修改。

批注来源回跳先持久化目标批注和应打开的标签，再由工作台消费并清空。这样输入区扩展和工作台 surface 即使独立挂载或中途重连，也不会丢失导航意图；无法定位原文时仍展示不可变快照。

## 迁移

首次读取 schema v1 时，Sift 先复制整个数据目录为带时间戳的备份，再写入 schema v2。旧素材按引用项目的解决方案归属；跨解决方案引用拆成多个关系记录，但继续指向同一原位置。无项目引用的素材进入首页“待归类素材”，可明确选择解决方案后归档。旧批注保留原文，缺少的定位以不可用锚点表示。

旧解决方案的 `workspaceId` 和路径均为空，首次进入必须由用户明确选择；不会绑定当时 DSH 的当前工作区。早期 schema v2 数据若只有路径，也会被视为未完成绑定，要求重新确认原生工作区。
