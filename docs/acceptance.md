# 初版验收说明

工程验收以隔离 DSH Home 中的真实界面和文件行为为准。两周真实使用只用于判断产品是否顺手，不应写成工程已经验证的结论。

## 自动检查

在仓库执行：

```powershell
pnpm check
pnpm test
pnpm build
pnpm verify:package
```

测试至少覆盖数据关系与版本冲突、素材移除后的批注快照、会话绑定隔离、AI 工具目标约束、发送失败/重复发送/发送中编辑，以及新旧 DSH 入口行为。

## 隔离实机

设置 `SIFT_DSH_SOURCE` 后运行 `pnpm dev:setup` 与 `pnpm dev`。逐项验证：

1. 首页创建解决方案并关联原生工作区，建立两个项目和各自讨论；切换普通 DSH 会话不改变项目关联。
2. 复用 Markdown、文本 PDF、DOCX、网页素材；检查只读阅读、鼠标选区批注、聚焦阅读器后 `Ctrl+A` 的键盘选区、来源回跳和失效后重新定位；在 DSH 原生消息上同样验证选区批注和消息位置回跳。
3. 核对发送预览与原生实际用户消息一致，包括纯批注、重复、排队、失败和发送期间修改评论。
4. 让 AI 修改当前笔记并查看差异；验证它不能看到 shell、通用写入、子代理，也不能修改素材、其他项目笔记或关系数据。
5. 制造外部文件变化与并发版本冲突；确认干净编辑器自动刷新，草稿进入显式合并，回退不会覆盖后续版本。
6. 刷新并交叉进入项目，确认标签、阅读位置、草稿、批注选择和布局宽度分别恢复。
7. 返回普通 DSH 页面，再卸载插件，确认原生首页、会话、输入框与工具行为恢复。

`.doc`、扫描 PDF OCR、登录网页抓取和 Office 高保真编辑只需显示明确的不支持状态与原文件位置。
