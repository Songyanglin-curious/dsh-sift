# 开发与验证

本文记录当前 Sift 仓库的开发入口和验证边界。产品定位与核心对象见仓库根目录的 `README.md`，实际操作见[使用流程](使用流程.md)。

## 环境要求

- Node.js 24 或更高版本。
- pnpm 11.25.0。
- 与当前插件接口匹配的 DSH 源码工作树。
- Windows PowerShell。

当前 `package.json` 的 DSH peer dependency 是 `0.1.5-rc.2`。开发脚本还会使用 `SIFT_DSH_SOURCE` 指向本机 DSH 源码；版本、接口和源码状态都可能变化，不能只根据本文判断兼容性。

## 安装与自动检查

```powershell
pnpm install
pnpm check
pnpm test
pnpm build
```

- `pnpm check`：TypeScript 静态检查。
- `pnpm test`：Vitest 自动测试。
- `pnpm build`：生成 Host、Client 与类型产物。
- `pnpm verify:package`：在隔离环境验证 tarball、安装、组合配置、文件完整性和卸载。

自动检查通过只能证明相应代码路径没有发现问题，不能代替真实浏览器中的交互验收。

## 隔离开发环境

日常开发使用仓库内的 `.debug/development` 作为独立 `DSH_HOME`，通过 `link:` 加载当前源码，不修改正式 DSH Home 或正式 Profile。

```powershell
$env:SIFT_DSH_SOURCE = 'D:\mycode\deepseek-harness'
pnpm dev:setup
pnpm dev
pnpm dev:status
pnpm dev:clean
```

开发 Web 默认监听 `http://127.0.0.1:9082`，可通过 `SIFT_DEV_PORT` 修改端口。

- Client 修改：重新构建最终 Client 产物，再由 DSH Client HMR 加载。
- Host、Bundle patch 或依赖修改：构建成功后受控重启 Host。
- 运行状态：使用 `pnpm dev:status` 查看，不以单个日志事件代替功能验证。

## 验证层级

1. 针对状态规则和 Store 执行单元测试。
2. 执行 `pnpm check`、`pnpm test` 和 `pnpm build`。
3. 在隔离 DSH Home 中确认插件和 Remote 服务挂载。
4. 在真实浏览器中验证 Reference、Output、关联关系、编辑器和原生会话交互。
5. 发布前执行 `pnpm verify:package`。

完整人工检查项见[验收说明](验收说明.md)。历史阶段的测试结果只证明当时的代码，不自动继承为当前版本的验证结果。

## Git 与发布边界

- 提交前检查工作区，保留用户已有和无关的修改。
- 提交信息使用中文。
- 未经明确授权，不提交、不推送，也不发布 npm 包。
