# dsh-sift v0.2 设计方案

> 历史设计：本文描述 v0.2 重构时的目标模型，其中部分目标尚未实现，部分交互已经被后续 Reference / Output 工作流替代。当前使用方式以 [`使用流程.md`](../使用流程.md) 为准。

## 1. 版本目标

v0.2 不再沿用 v0.1 的“素材区 + 项目/解决方案”思路。

v0.2 的目标是：

> **把 Sift 重构为 DSH 的一种 Workspace Profile，用 Source → Reference → Document 的工作流，帮助用户从大量原始信息中快速筛出当前有效参考，并低摩擦地形成和修改自己的 Markdown 笔记。**

核心不是知识管理，不是文件管理，也不是项目管理。核心是：

```text
大量信息 → 寻找 → 筛选 → 当前参考 → 思考 / 对话 → 产出
```

## 2. 产品定位

Sift 是 DSH 的一种 Workspace Profile。

```text
DSH
└── Workspace
    ├── profile = default   → DSH 原生体验
    └── profile = sift      → Sift 工作体验
```

Workspace 仍然是一级入口。Sift 不建立第二套 Workspace、Session、文件系统、Agent、模型配置，也没有项目/解决方案体系。Sift 只改变：**Workspace 中人如何组织输入、上下文和产出**。

## 3. v0.2 的核心推理

### 3.1 为什么不能继续以“素材文件”为核心

如果用户拥有 100 万字原始资料，最终只希望形成 1000～5000 字自己的笔记，那么过程不可能是「原始文件 → 最终笔记」。中间一定存在：搜索、定位、摘取、压缩、比较、核对、再次筛选。因此：**原始文件不是最终工作上下文。**

### 3.2 为什么不能把所有摘录都做成长期知识卡片

如果 Reference 成为长期 Workspace 资产，几十条会变成几百条，进而需要标签、搜索、分类、维护，Sift 会逐渐变成知识卡片系统。这不是目标。因此长期资产只保留两类：**Source 与 Document**。Reference 是工作过程中的中间态。

## 4. 核心对象

v0.2 只定义三个核心业务对象：`Source`、`Reference`、`Document`。Session 直接复用 DSH。

## 5. Source

### 5.1 定义

> **Source 是 Sift 能稳定访问的信息来源。**

Source 属于 Workspace，不要求一定存在于 Workspace 目录。它可以是 Workspace 内文件、本机其他目录文件、URL、由复制内容直接创建的 Workspace 文件、旧 Markdown 笔记、代码文件、PDF、DOCX、图片、其他可访问资源。

### 5.2 Source 不等于 Workspace Path

这是 v0.2 的明确原则。例如 `D:\Downloads\61850.pdf` 可以直接成为 Source，不要求复制到 Workspace。

同时，用户从微信、远端服务器、网页、聊天窗口复制了一段文字，可以直接：

```text
粘贴 → 输入文件名 → 在当前 Workspace 创建 xxx.md → 自动成为 Source
```

所以：**已有文件直接引用；没有文件形态的内容可以一步落成 Workspace 文件。**

### 5.3 Source 的入口

第一版支持：

- **工作区文件**：直接选择。
- **本机外部文件**：通过系统文件/目录能力选择，保存绝对路径。
- **拖拽文件**：如果能够取得原始路径，直接引用；如果浏览器只能取得文件内容，则提供「导入到 Workspace」。
- **URL**：直接记录 URL，后续可以扩展网页抓取。
- **粘贴创建文件**：例如 `+ 新建来源文件`，粘贴内容并命名，保存为 `workspace/<名称>.md`，同时登记为 Source。

## 6. Reference

### 6.1 定义

> **Reference 是当前 Document 为了思考和写作正在使用的有效工作材料。**

Reference 不等于文件。它可能是完整短文件、PDF 中某几页的信息、源码中的一个方法、网页中的一段、AI 从多个 Source 中提炼出的几条事实、用户临时粘贴的一段话、用户自己的临时说明。核心判断只有一个：**这个内容现在是否值得占据我的注意力？**

### 6.2 Reference 属于 Document

```text
Workspace
├── Sources
└── Documents
    ├── A.md → Reference Board
    └── B.md → Reference Board
```

Reference 不建立 Workspace 级知识库。切换 Document 时，Reference Board 随之切换。

### 6.3 Reference 是短期但可恢复的

Reference 不是一次性的内存数据，需要保存，因为用户第二天回来还要继续。但它的生命周期依附于 Document。关闭 Workspace 再打开仍然恢复；用户删除这篇 Document 或明确清空 Reference Board 后，这些 Reference 没有独立存在的必要。

## 7. Document

### 7.1 定义

> **Document 是用户真正准备长期维护和留下的正式产出。**

Document 第一版统一使用普通 Markdown。Sift 不发明新的笔记格式。

### 7.2 未命名 Document

创建 Sift Workspace 时自动打开一个 `Untitled Document`，逻辑状态 `path = null`。用户可以加 Source、生成 Reference、讨论、开始写。第一次保存时 `path = null` 变成 `path = notes/xxx.md`，Reference Board 不变化。不需要 Scratch Board 这个第二概念。

## 8. Session

Session 完全复用 DSH。Sift 不修改 Session 生命周期、模型配置、Tool 调度、Agent Loop、历史记录。Sift 只需要提供：**当前 Reference 如何低摩擦地进入 Session Context**。这是 v0.2 最关键的验证点之一。

## 9. 主界面

Sift Workspace 使用三栏：

```text
┌────────────────────┬────────────────────┬────────────────────┐
│ Reference Board    │ Document           │ DSH Session        │
│ 当前有效参考        │ Markdown           │ 原生对话            │
│ 内容一级展示        │ Diff               │ AI分析              │
│ 多选               │ 局部批注            │ 搜索 / 比较 / 修改   │
└────────────────────┴────────────────────┴────────────────────┘
```

逻辑上还有第四部分 `Workspace Sources`，但不常驻第四栏，通过 `+ 从来源获取` 临时打开 Source Drawer。

## 10. Source Drawer

Source 不应该长期占据主界面。点击 `+ 从来源获取` 展开：

```text
┌────────────── 来源 ──────────────┐
│ □ architecture.md               │
│ □ workspace.ts                  │
│ □ 61850.pdf                     │
│ □ D:\Downloads\xxx.docx         │
│ □ https://...                   │
│                                 │
│ + 添加文件                      │
│ + 添加网页                      │
│ + 粘贴并创建文件                │
│                                 │
│ [整份加入当前参考]               │
│ [让 AI 从所选来源提取参考]        │
└─────────────────────────────────┘
```

Source Drawer 解决「我手里有哪些原始输入」；Reference Board 解决「我现在真正用哪些信息」。

## 11. Source → Reference

这是 v0.2 最核心的交互。第一版支持三种方式。

### 11.1 整份加入

适合短 Markdown、小文本、小代码文件、短粘贴内容。操作：`Source → 整份加入当前参考 → Reference`。

### 11.2 AI 提取

这是 v0.2 的主路径。例如用户选择 `architecture.md`、`workspace.ts`、`issue-123`，然后在 Session 中说「从这些来源里找出能说明 Workspace 定位的内容」。AI 返回候选：

```text
① Workspace 与已有目录绑定……
② 相同路径复用已有 Workspace……
③ 删除 Workspace 不删除目录……
```

用户勾选 `✓① ✓② ×③`，点击「加入当前参考」，左侧直接出现两张 Reference。

### 11.3 直接粘贴 Reference

用户有时候已经知道自己要什么。直接 `+ 粘贴参考` 立即生成 Reference，不强制先变成 Source。如果以后发现这段内容值得长期保留，可以「保存为文件」，直接在 Workspace 创建 Markdown。

## 12. Reference Board

Reference Board 第一版采用**结构化卡片板，而不是无限白板**。卡片一级展示内容：

```text
┌──────────────────────────────┐
│ Workspace 与实际目录绑定      │
│                              │
│ Workspace 注册的是已有目录…… │
│                              │
│ 来源：architecture.md        │
└──────────────────────────────┘
```

不采用「先看文件名、点击才能看正文」，因为 Reference 的核心价值就是：**让用户一眼看到自己当前基于什么思考。**

## 13. Reference Board 第一版能力

只做：一级展示、选择、多选、移出、查看来源、复制内容、发送给 Session。

第一版暂不做：自由坐标、无限画布、连线、复杂分组、标签、Reference 全局搜索、知识图谱。

## 14. Reference 的使用

只有三个主要用途：

- **给人看**：直接铺开，帮助人快速对比和记忆当前上下文。
- **给 AI 看**：选择 `R1 R3 R5`，然后说「基于当前选择分析……」，无需重新复制内容或反复 @ 文件。
- **支撑 Document**：例如「根据 R1、R3、R5 修改当前章节」，AI 直接修改 Document。

## 15. Document 编辑

中间区域是 Markdown + AI Diff + 局部批注。AI 可以直接修改文档，但任何 AI 修改必须经过 `AI修改 → Diff → 接受 / 拒绝`。对于局部问题：选择一段 → 添加批注 → 让 AI 修改 → Diff。

目标是：**像审查代码一样审查 AI 对知识文档的修改。**

## 16. 从 0 开始完整使用流程

1. 创建 Sift Workspace，自动打开 Untitled Document。
2. 加入 Source：工作区内 `architecture.md`；本机外部 `D:\Downloads\DSH.pdf`；网页 `https://...`；远端复制内容粘贴创建 `remote-notes.md`。
3. 用户提出当前问题：「我想先搞清楚 Workspace 到底负责什么。」
4. 打开 Source Drawer，选中 `architecture.md`、`DSH.pdf`、`remote-notes.md`，点击「让 AI 从所选来源提取参考」。
5. AI 返回候选 Reference，用户确认其中几条，左侧一级展示。
6. 用户多选几条 Reference：「根据这些内容写一个 Workspace 基本职责小节。」AI 修改中间 Untitled Document，显示 Diff，用户接受。
7. 保存为 `DSH Workspace理解.md`，Reference Board 自动绑定到该 Document。
8. 写到 Session 部分时发现信息不足，继续 Source Drawer → 选择源码 → 让 AI 查找 → 生成新 Reference → 继续修改 Document。
9. 某些 Reference 用完，移出当前 Reference Board，不会删除 Source。
10. 最终留下 Workspace Sources + 正式 Markdown Documents。Reference 是完成这些 Document 时的工作上下文。

## 17. 信息压缩模型

三次信息收紧：

| 层 | 量级 | 代表 |
| --- | --- | --- |
| Source | 100 万字 | 我有哪些信息 |
| Reference | 3000～10000 字 | 我现在真正依据什么 |
| Document | 1000～5000 字 | 我最终决定留下什么 |

```text
Source → AI搜索 / 人提出方向 → Reference → 人筛选 / AI辅助组织 → Document
```

AI 主要承担搜索、定位、第一轮压缩、比较、改写；人主要把控问题方向、Reference 边界、结论是否成立、最终 Document。

## 18. v0.2 数据模型

```ts
interface SiftWorkspaceConfig {
  version: '0.2'
  profile: 'sift'
}

interface Source {
  id: string
  type: 'file' | 'url'
  title: string
  target: string
  location?: 'workspace' | 'external'
  createdAt: string
}

interface DocumentState {
  id: string
  path: string | null
  title?: string
}

interface Reference {
  id: string
  documentId: string
  content: string
  sourceId?: string
  locator?: string
  note?: string
  createdAt: string
}
```

其中 Workspace 文件 `target` = 相对路径；外部文件 `target` = 绝对路径；URL `target` = URL。复制粘贴创建的 Markdown 本质直接成为 `type = file`、`location = workspace`。

第一版不增加 `parentReference`、`groupId`、`tags`、graph edges、global index。

## 19. 文件存储

```text
workspace/
├── .sift/
│   ├── config.json
│   ├── sources.json
│   └── documents.json
├── notes/
│   └── DSH Workspace理解.md
└── remote-notes.md
```

Reference 状态可以保存在 `documents.json`，或者后续按 Document 单独拆。第一版以简单为先。

## 20. v0.2 必须完成的能力

- **Workspace**：创建 Sift Workspace、Profile 识别、Default Workspace 不受影响。
- **Source**：工作区文件、本机外部文件、URL、粘贴创建 Workspace Markdown、查看 Source、移除 Source 关系。
- **Reference**：整份 Source → Reference、AI 从 Source 生成候选 Reference、粘贴直接生成 Reference、一级展示、多选、移出、查看来源。
- **Document**：Untitled Document、Markdown 保存、切换 Document、每个 Document 独立 Reference Board、AI 修改、Diff。
- **Session**：原生 DSH Session、Selected References → Session Context、Session → 修改当前 Document。

## 21. v0.2 明确不做

不做：Solution、Project、Task、Workspace Reference Library、Reference 标签系统、Reference 全局搜索、无限白板、知识图谱、PDF 自研阅读器、DOCX 自研阅读器、网页复杂阅读模式、自动知识库、自动分类、自动生成完整笔记、云同步。

## 22. 旧版迁移原则

> 架构重新实现，旧代码只按能力挑选复用。

优先保留：DSH Web 注入方式、Workspace 接入能力、文件选择相关代码、Markdown 编辑器、Diff 能力、Session 接入、有价值的预览组件。

优先废弃：Solution 模型、Project 模型、旧 Materials 数据模型、旧素材标签逻辑、两套重复 UI、围绕旧组织模型产生的状态管理、复杂兼容逻辑。

不要为了复用代码破坏 v0.2 模型。

## 23. 开发顺序

- **Phase 1：Workspace Profile** —— 只验证 `default` / `sift` 工作区切换可以正确加载不同主界面。
- **Phase 2：三栏骨架** —— 实现 `Reference | Document | Session`，Session 完全复用原生能力。
- **Phase 3：Source** —— 工作区文件、外部文件、粘贴创建 Markdown、Source Drawer。
- **Phase 4：Reference** —— `Source → Reference`，先支持整份加入、粘贴加入、卡片显示。
- **Phase 5：Session Context** —— 打通「选择 Reference → DSH Session」，第一个真正的产品验证节点。
- **Phase 6：AI 提取 Reference** —— 打通「选 Sources → 让 AI 找 → 候选 Reference → 确认」。
- **Phase 7：Document AI Diff** —— 打通「Reference → Session → 修改 Document → Diff」，到这里 v0.2 核心闭环完成。

## 24. v0.2 的成功标准

不看功能数量，只看三个场景：

1. 我有 10 个来源，能否快速得到 5 条当前真正有价值的 Reference。
2. 我进入页面后能否一眼看到「我现在到底依据什么在思考」。
3. 能否做到「选 Reference → 问 AI → 直接修改 Document → Diff → 继续」。

这三条足够顺，v0.2 成立。

## 25. 最终定义

```text
外部世界（文件 / 网页 / 复制内容 / 远端内容）
        ↓
      Source          —— 信息从哪里来
        ↓
   AI + 人筛选
        ↓
    Reference        —— 我现在依据什么
        ↓
   人 + AI思考
        ↓
     Document        —— 我最终留下什么
```

Session 是人和 AI 完成中间加工的地方。

Sift 的核心不是管理知识，而是：**让大量信息经过尽可能低摩擦的人机协作，逐渐收紧成自己的理解和笔记。**
