# 当前验收说明

工程验收以当前代码、隔离 DSH Home 和真实界面行为为准。自动检查、运行时挂载和人工浏览器验收必须分别记录；不能用构建成功代替真实交互通过。

## 自动检查

```powershell
pnpm check
pnpm test
pnpm build
pnpm verify:package
```

自动测试至少应覆盖：

- Workspace Profile 识别、缺失回退与工作区隔离。
- Reference 创建、保存、删除和损坏数据保护。
- Reference 卡片粘贴、编辑、删除、排序和 Undo/Redo。
- Output 新建、添加已有、切换、外部打开和磁盘同步。
- Relation 的缺失与明确空关系区分。
- 新建 Output 继承当前 References，已有关系不被覆盖。
- Output 移除/删除和 Reference 删除后的关系清理。
- “本轮批注”的选区坐标、序列化、分隔线、编辑与移除。
- AI 修改工具不接受路径或 Document id，只写当前绑定 Document。
- 工作区路径越界和非 Markdown Output 拒绝。

## 隔离运行验证

设置 `SIFT_DSH_SOURCE` 后运行：

```powershell
pnpm dev:setup
pnpm dev
pnpm dev:status
```

确认：

1. Sift Host、Remote 和工具服务均已挂载。
2. `default` 工作区保持 DSH 原生界面。
3. `sift` 工作区显示参考、文档和原生对话三栏。
4. Client 改动能加载最新构建产物；Host 改动完成受控重启。
5. 停止后没有遗留开发监听端口或错误归属的进程。

## 真实浏览器主流程

### Workspace

1. 分别创建 `default` 和 `sift` 工作区。
2. 重启开发实例后确认类型仍能恢复。
3. 快速往返切换，确认旧异步结果不会污染当前工作区。

### Reference

1. 空工作区不会自动创建或打开 Reference。
2. 分别验证新建与添加已有，它们必须是两个独立动作。
3. 粘贴纯文本、网页内容和文件引用，确认生成的卡片与来源正确。
4. 验证编辑、删除、拖动排序、来源打开和 Undo/Redo。
5. 无活动 Document 时关闭 Reference Tab，确认物理文件仍存在。
6. 永久删除 Reference 前必须确认，删除后所有相关 Relation 被清理。

### Document

1. 新建 Markdown，确认文件和 `.sift/documents.json` 正确落盘。
2. 添加已有 `.md`，拒绝非 Markdown 文件。
3. 多个 Document 之间切换，确认只读正文不串。
4. 用外部编辑器打开并修改文件，验证手动同步、切换同步和窗口聚焦同步。
5. 双击修改标题；分别验证“移除但保留文件”和“永久删除文件”。

### Relation

1. 无 Document 时建立自由 Reference 工作集。
2. 新建 Document，确认继承创建前可见的 References。
3. 给两个 Document 配置不同 References，切换时左侧正确变化。
4. 切换 Document 前后检查 Relation 文件没有被隐式改写。
5. 添加已有 Document 时，已有关系和明确空关系都不会被覆盖。
6. 使用“编辑关联参考”保存后，左侧立即同步。

### 原生会话与本轮批注

1. 在 Reference 卡片和 Document 正文分别创建选区批注。
2. 确认原文、来源对象和批注内容进入 DSH 原生输入框。
3. 验证 Enter 提交、Shift+Enter 换行、编辑、移除、分隔线和多个批注共同发送。
4. 使用 DSH 原生发送、停止、模型和工具界面，确认没有第二套会话流程。
5. 切换到普通 DSH 会话，确认 Sift 不污染原生输入行为。

## 当前不应报告为已通过

以下能力尚未完成或没有完整证据时，必须明确写为未验证：

- Source Drawer 与完整 Source → Reference 流程。
- AI 从多个 Source 提取候选 Reference。
- Reference 通过正式 Reference Codec 进入 Session 的完整手感。
- AI 修改当前 Document 后的真实模型调用与浏览器同步手感。
- 两周真实使用形成的产品体验结论。
