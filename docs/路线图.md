# 路线图

本文只记录当前尚未完成的产品主链。已经完成的阶段及其证据保存在[历史文档](archive/index.md)，不再作为执行计划重复维护。

## 当前基线

目前已经具备：

- default / sift 工作区类型区分；
- Reference 的新建、添加已有、卡片编辑、排序、来源与持久化；
- Output Markdown 的新建、添加已有、切换、重命名、移除和删除；
- Output 与 References 的显式关联；
- Reference / Output 选区形成“本轮批注”并进入 DSH 原生输入框；
- DSH 原生 Markdown 只读展示、外部编辑器打开与手动/轻量自动同步；
- AI 通过目标固定工具直接修改当前 Document。

## 下一阶段

### 1. 收紧 AI 交互边界

继续保持“本轮批注”为进入原生 DSH Session 的最薄适配。Sift 不发展第二套聊天、持久批注历史或复杂发送协议。

### 2. 恢复 Source → Reference 主链

- 明确 Source 的登记与访问方式。
- 支持工作区文件、本机文件、URL 和粘贴内容。
- 支持从短 Source 直接形成 Reference。
- 支持从多个 Source 搜索、定位并生成少量候选 Reference。
- 候选内容必须由用户确认后才能进入 Reference。

### 3. 打通 Reference → Session

- 选择当前真正需要的 Reference。
- 使用 DSH 官方输入引用机制进入原生会话。
- 明确模型实际收到的 Reference 内容。
- 不在 UI 中自行拼接另一套隐式 Prompt。

### 4. 完成真实使用验证

- 补齐真实浏览器中的主流程验收。
- 验证 AI 只能修改当前 Document，修改后自动或手动同步可见。
- 记录自动检查与人工验收各自覆盖的范围。
- 通过持续使用验证中断恢复、跨主题复用和 Markdown 脱离 Sift 后的可用性。

## 暂不扩展

- Reference 标签、全局知识库和知识图谱。
- 向量数据库和复杂自动分类。
- 第二套会话、模型选择或发送流程。
- 用算法判断用户是否已经掌握。
- 为尚未出现的多用户、多窗口和云同步需求提前设计复杂框架。
