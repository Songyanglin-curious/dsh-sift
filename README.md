# Sift

从混杂内容中筛选、整理出真正有价值的知识。

## 项目定位

Sift 是一个先服务个人的、由 AI 协作的学习型知识梳理工作台。

它帮助用户把低密度、零散、相互矛盾且经过多次纠正的材料，按照自己的判断逐步梳理成一篇结构清晰、真正认可、能够继续使用和直接分享的本地 Markdown 笔记。

Sift 的核心价值不是替人总结，而是让人在亲自选择、判断、修改和组织内容的过程中完成学习。

## 核心原则

- **人掌握判断权**：人决定梳理目标、知识结构、内容正误，以及笔记何时完成。
- **AI 只推进一小步**：AI 每次提出一个容易理解和审核的小修改，由人接受、修改、否定或继续讨论。
- **持续收敛，而非制造碎片**：素材、批注和对话都是加工依据，最终成果持续汇集到笔记中。
- **不量化人的掌握程度**：Sift 不设置掌握度或完成算法。是否真正掌握，只有使用者自己知道。
- **内容优先**：优秀的个人笔记本身就可以成为博客，首阶段不追求复杂的发布样式。
- **内容与关系分离**：原始文件保持独立，Sift 只管理引用、元信息和组织关系。

## 核心循环

```text
明确当前目标
    ↓
选择相关素材
    ↓
AI 提出一个小的知识修改
    ↓
人接受、修改、否定或继续讨论
    ↓
结果写回 Markdown 笔记
    ↓
根据新的理解决定下一步
```

这个循环同时作用于结构和内容：写一点结构，填一点内容，发现缺口或矛盾，再回到素材中验证和修正。

## 组织模型

- **素材**：对话、网页、代码、文档以及其他本地文件或 URL。
- **项目**：以一篇本地 Markdown 笔记为成果中心，关联本次梳理所需的素材和过程信息。
- **解决方案**：围绕一个主题组织多个相关项目。

素材和笔记不必存放在 Sift 的固定目录中。同一份素材可以被多个项目引用；移除引用不应删除原始内容。笔记始终是用户能够直接访问和控制的普通文件。

## 第一阶段目标

第一阶段不是完成一次演示，而是让 Sift 成为可以连续使用的日常工具。方向成立需要经过至少两周的真实使用，并满足：

- 能处理日常遇到的对话、网页、代码和文档等零散材料。
- 能围绕一篇笔记持续搭建结构、补充内容、纠正错误和改进表达。
- 每次 AI 修改都足够小，并且可以理解、编辑和拒绝。
- 中断后能够恢复当前目标、材料关系和整理进度。
- 最终 Markdown 脱离 Sift 后仍然完整、可复用，也可以直接作为分享内容。
- 使用者愿意继续用它处理新的真实主题。

## 首阶段暂不解决

- 大型个人知识库或收藏系统。
- 自动判断用户是否已经掌握。
- 一次性生成整篇内容，再交给用户被动验收。
- 复杂知识图谱、向量检索、间隔复习和自动测验。
- 精美博客排版、发布平台和多端同步。
- 多人协作及面向广泛用户的通用化设计。

## 为什么使用 DSH

Sift 将以 DSH 插件的形式实现，利用其 AI 能力和 Web 可视化基础降低交互开发成本。同时，这也是一个通过真实产品开发逐步学习 DSH 插件体系的项目。

产品闭环是否真正有用是首要目标；学习 DSH 插件开发是次要目标。

## 当前状态

项目处于目标确认和初期设计阶段，功能、数据结构与交互细节仍在探索中。
